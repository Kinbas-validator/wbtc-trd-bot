# Telegram-уведомления о WBTC Market TRD

## Что подготовлено

Python 3.10+ без сторонних библиотек. Отдельный процесс отправляет сообщения через существующего Telegram-бота. Он не устанавливает webhook и не забирает входящие сообщения: его можно использовать рядом с другим приложением этого же бота.

Рынок: https://yieldbasis.com/analytics/market/0x651D4b8168488FA163D85304662E8278d4c55BAa

- Проверка раз в 60 секунд.
- Уведомления при пересечении вверх −1,0%, −0,5% и 0%.
- Каждый порог уведомляет один раз за время жизни сохранённого состояния. Колебания около порога не вызывают повторных сообщений.
- При скачке через несколько порогов отправляются сообщения по всем пройденным порогам.
- При первом запуске отправляется текущий статус. Уже достигнутые уровни считаются пройденными; прошлое движение не восстанавливается.
- Нулевой порог означает фактический TRD ≥ 0. Округление отрицательного числа на сайте до 0,00% не считается нулём.
- SQLite хранит предыдущую выборку, пройденные пороги и очередь доставки. После рестарта история сохраняется.
- После 5 минут ошибок источника бот предупреждает об отсутствии свежих данных; после восстановления сообщает об этом.
- Краткое движение между проверками может быть пропущено. Проверка раз в минуту — не гарантия мгновенного сообщения.
- При потере ответа Telegram после фактического получения сообщения возможна повторная доставка. Bot API не предоставляет ключ идемпотентности для sendMessage.

## Источник данных и проверка

Официальная формула: https://docs.yieldbasis.com/dev/overview
Подробности: https://docs.yieldbasis.com/dev/integration/deposit-withdraw
Адреса: https://docs.yieldbasis.com/user/reference/contract-addresses
Код контрактов: https://github.com/yield-basis/yb-core

TRD (%) = (preview_withdraw(10**18) * 10**10 / pricePerShare() − 1) * 100.
WBTC имеет 8 десятичных знаков, pricePerShare — 18. Значения читаются из одного блока Ethereum mainnet. Проверяются адрес базового актива, его decimals, свежесть блока и отсутствие смены его hash во время чтения. Бот только читает данные, кошелёк не нужен.

**Статус:** формула и адрес сверены с документацией и исходниками, автономные тесты выполнены. Живое чтение Ethereum, совпадение с текущим значением интерфейса, запуск на VPS ещё требуют проверки. Доставка тестового сообщения через Telegram Bot API проверена. Установщик самостоятельно проверяет живые данные с VPS перед запуском. Тесты используют имитацию RPC, а не блокчейн.

## Установка одной командой — Ubuntu 24.04

Откройте своего бота в Telegram и нажмите **Start**. Подключитесь по SSH к серверу и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Kinbas-validator/wbtc-trd-bot/main/install.sh | sudo bash -s -- --chat-id YOUR_CHAT_ID
```

Замените `YOUR_CHAT_ID` вашим числовым Telegram chat ID. Если вы вошли как root и sudo не установлен, используйте `bash -s` вместо `sudo bash -s`.

Установщик попросит подтвердить chat ID (Enter) и вставить токен BotFather скрытым вводом. Он установит системные зависимости, выполнит тесты, проверит реальные данные Ethereum, отправит тест в Telegram и включит systemd-сервис с автозапуском. Ввод идёт через `/dev/tty`, поэтому команда работает и через pipe.

По умолчанию используется публичный RPC `https://ethereum-rpc.publicnode.com`, указанный на https://ethereum.publicnode.com/. Отдельная регистрация не нужна. Если он недоступен с сервера, установщик даст повторить проверку или ввести свой HTTPS Ethereum mainnet RPC. Бесплатный публичный endpoint не гарантирует доступность; при необходимости замените его своим.

Для установки определённой версии используйте SHA коммита вместо `main` в URL и передайте тот же SHA аргументом `--ref SHA`.

### Где всё хранится

- Программа: `/opt/trd-bot/bot.py`.
- Токен, chat ID, RPC: `/etc/trd-bot.env` (root, права 600).
- Состояние и очередь: `/var/lib/trd-bot/state.sqlite3`.
- Сервис: `/etc/systemd/system/trd-bot.service`.

Токен и chat ID не встроены в репозиторий. Установщик отправляет только тест в указанный вами чат; webhook и входящие сообщения существующего бота не меняет.

### Управление

```bash
sudo systemctl status trd-bot --no-pager
sudo journalctl -u trd-bot -f
sudo systemctl restart trd-bot
sudo systemctl disable --now trd-bot
```

Повторный запуск команды установки обновит программу, сохранив историю пройденных уровней. Прежний токен можно оставить нажатием Enter. Конфигурация заменяется только после успешной проверки данных и Telegram. При смене chat ID потребуется отдельная история состояния; установщик остановится, если существующая база относится к другому чату.

Для нового цикла наблюдения остановите сервис, сохраните каталог состояния под другим именем и снова запустите. Новое состояние начнётся с актуального TRD; прошлые движения не восстанавливаются.

```bash
sudo systemctl stop trd-bot
sudo mv /var/lib/trd-bot /var/lib/trd-bot.backup-$(date +%Y%m%d-%H%M%S)
sudo systemctl start trd-bot
```

## Автономные тесты

```bash
python3 -m unittest -v
```

Покрывают масштаб WBTC, направления пересечений, скачок через несколько уровней, точный ноль, перезапуск, очередь после ошибки Telegram, сбой/восстановление источника, неправильную сеть и устаревшие блоки.
